API v1 · base https://api.sanctumsecops.org

API reference

The log is the product surface; the website is a convenience wrapper. Open-tier endpoints require no authentication. Attested and automation endpoints authenticate with an X-API-Key header bound to an enrolled organisation.

Media type application/json Digests sha256: prefixed hex Times RFC 3339 UTC Errors RFC 9457 problem+json

Contract, not deployment. This documents the intended interface so integrators can build against a stable shape. The endpoints are not yet serving on this domain.

Open tier — no authentication

POST/log/append public

Submit a digest for inclusion in the next aggregation window. Idempotent per digest within a window.

Request / response
// request
{ "digest": "sha256:9f2b41c8…" }

// 202 Accepted
{ "leaf": 1284417,
  "pending_window": "2026-08-27T18:05:00Z",
  "receipt_url": "/log/inclusion-proof?digest=sha256:9f2b41c8…" }
GET/log/tree-head public

Latest signed tree head. Watchers should poll this and retain history — retained tree heads are what make operator misbehaviour provable.

200 OK
{ "tree_size": 1284418,
  "root_hash": "3ae0…",
  "timestamp": "2026-08-27T18:04:11Z",
  "signature": {
    "scheme": "composite",
    "ecdsa_p256": "MEUCIQD…",
    "ml_dsa_65": "kR3nA9…" } }
GET/log/inclusion-proof public

Audit path for a digest. Query by digest or leaf. Returns the full receipt body. 404 until the containing window is sealed.

GET/log/consistency-proof public

Proof that tree ?first=n is a prefix of ?second=m. The endpoint a watcher uses to confirm the log has only ever been appended to.

GET/log/verify public

Server-side convenience check of a submitted receipt. Provided for tooling, but offline verification is the intended path and always will be — never require this endpoint.

Attested tier — X-API-Key

POST/attest/append api key + piv signature

Submit a digest together with a signature produced by an enrolled YubiKey PIV slot. The server validates the attestation chain against the enrolled token before accepting.

Request
{ "digest": "sha256:9f2b41c8…",
  "signer_id": "sso:signer:0142",
  "piv_signature": "MEQCIF…",
  "piv_slot": "9c" }
POST/attest/batch api key

Up to 1,000 digests per call for CI/CD and bulk anchoring. Metered against the automation allowance.

GET/signers/{signer_id} public

Public signer registry entry: organisation, verification method used at enrollment, attestation certificate, enrollment and revocation timestamps. Public by design — an identity claim nobody can look up is not an identity claim.

POST/signers/{signer_id}/revoke api key

Immediately revokes a token. Never billed and never rate-limited — expensive revocation produces unrevoked compromised keys.

Receipt format

Self-contained by design. Everything a verifier needs is inside the file.

receipt v1 — attested example
{
  "version": 1,
  "log": "sanctumsecops.org/log/v1",
  "digest": "sha256:9f2b41c8…",
  "leaf_index": 1284417,
  "tree_size": 1284418,
  "audit_path": ["7c1d…", "a03f…", "…"],
  "tree_head": {
    "tree_size": 1284418,
    "root_hash": "3ae0…",
    "timestamp": "2026-08-27T18:04:11Z",
    "signature": { "scheme": "composite",
                    "ecdsa_p256": "…",
                    "ml_dsa_65": "…" }
  },
  "attestation": {
    "signer_id": "sso:signer:0142",
    "organization": "Example Defense Systems Inc",
    "verified_by": "cage",
    "piv_slot": "9c",
    "piv_attestation_chain": ["MIIC…", "MIIC…"],
    "signature": "MEQCIF…"
  }
}

Open-tier receipts are byte-identical except that attestation is null. A verifier must treat a null attestation as proof of when only, and must never infer authorship from log membership alone.

OpenTimestamps compatibility

Stated design target. Not yet implemented.

The commitment

Compatibility means a .ots receipt emitted here is consumable by standard OpenTimestamps clients without Sanctum-specific software, and that digests can be cross-anchored so a proof survives this service ceasing to exist. Anything less is not compatibility, and calling it that would be dishonest.

Where it actually stands

No OpenTimestamps implementation exists in the codebase today — the term appears only in documentation. The native Merkle log, proofs, and composite tree-head signing are real and tested. Serialising to the .ots format and cross-anchoring are open work items, not shipped features.
